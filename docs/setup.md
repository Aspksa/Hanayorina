# Hanayorina

Начальная основа проекта на TypeScript: локальная страница и запуск в Windows. Дополнительные функции ещё не реализованы.

## Запуск в Windows

Распакуйте весь проект в доступную для записи папку на компьютере, внешнем SSD или флешке и запустите `Hanayorina.bat`. Выберите запуск или диагностику. Для первого запуска нужен интернет.

Если подходящего Node.js нет, программа предложенной версией установит переносной Node.js 22.23.4 с официального сайта в `.runtime/node` и проверит SHA-256 по файлу контрольных сумм, полученному с того же сайта по HTTPS. Это проверка целостности, не отдельная проверка цифровой подписи. Для обновления этой версии потребуется обновление проекта. Windows x64 и ARM64 поддерживаются автоматической установкой. Действующую папку с неработающим Node.js программа не удаляет: переименуйте её самостоятельно после проверки содержимого.

BAT проверяет зависимости и при обнаружении повреждения запускает `npm ci` — эта команда переустанавливает `node_modules`, не затрагивая `.env` или базу. При проблемах загрузки проверьте доступ к nodejs.org и registry.npmjs.org. Если порт 4173 занят, выбирается свободный из диапазона 4173–4193. Браузер открывается после ответа именно запущенного сервера. Оставьте окно открытым. PostgreSQL проверяется при запуске; в меню диагностики проверка подключения выполняется без изменения таблиц. Для остановки нажмите Ctrl+C.

Пути с пробелами и кириллицей предусмотрены; при проблеме сообщите текст ошибки и путь без личных данных. Для ручного запуска: `npm ci`, `npm run build`, `npm start`.

## Локальная база PostgreSQL

PostgreSQL устанавливается отдельно и должен быть запущен. Создайте отдельные базу `hanayorina` и пользователя с правами создавать таблицы в этой базе. Пароль задайте самостоятельно. Это можно сделать через pgAdmin. Для надёжности регулярно создавайте резервные копии базы средствами PostgreSQL.

Скопируйте `config/.env.example` в `.env` в папке проекта и укажите реальные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` и `PGPASSWORD`. Файл `.env` содержит пароль: не публикуйте и не отправляйте его. Он исключён из Git. При обновлении проекта не заменяйте ваш `.env`.

Запустите `Hanayorina.bat`. При заполненных PGHOST, PGDATABASE и PGUSER приложение проверит соединение и создаст начальные таблицы, сохраняя существующие данные. Повторный запуск не создаёт таблицы заново. Если соединение не удалось, запуск остановится с сообщением в окне: проверьте службу PostgreSQL, настройки, права и пароль. Без настройки подключения стартовая страница запускается без базы.

Созданы таблицы для чатов, сообщений, памяти, агентов и их задач, документов, связей и настроек. История чатов сохраняется в таблицах PostgreSQL. Фоновая обработка явных фактов и поиск по словам доступны; смысловой поиск требует дополнительной настройки pgvector и эмбеддингов. Сам PostgreSQL и база не устанавливаются и не создаются автоматически.

## Ключи модели

После запуска откройте настройки, укажите базовый HTTPS-адрес OpenAI-совместимого API (обычно он оканчивается на `/v1`), добавьте ключи кнопкой «+ Ключ» и нажмите «Проверить соединение». Проверка обращается к `/models`; наличие конкретной модели и генерацию ответа она не проверяет. Некоторые сервисы не поддерживают этот маршрут или Bearer-авторизацию.

При включённом автоматическом переключении проверка последовательно пробует ключи при HTTP 401 или 402. При 429 выполняется не более одного повтора с учётом Retry-After (автоматически только при ожидании до 3 секунд), без смены ключа; при 502, 503 и 504 — один повтор через секунду. При 524 резервный адрес нужно проверить у поставщика и указать вручную. При других ошибках и недоступном сервере перебор не выполняется. Успешный ключ становится активным. Несколько ключей одного аккаунта могут иметь общий лимит. Отправка каждого запроса зависит от условий и тарифа поставщика.

Ключи хранятся в `data/model-keys.json` внутри проекта без шифрования; папка `data` исключена из Git. Защитите доступ к папке и не отправляйте файл другим. Значения после добавления не отображаются. Перенос проекта вместе с папкой `data` переносит и ключи. Чат использует выбранную модель и ключи основного сервиса.

### Резерв Cloud.ru

В разделе «Cloud.ru — резерв» можно сохранить отдельный ключ Foundation Models и включить резервную проверку. Если проверка основного API не прошла, приложение проверит Cloud.ru через `https://foundation-models.api.cloud.ru/v1/models` и сообщит об этом. Ключи сервисов не смешиваются. Самостоятельная кнопка «Проверить Cloud.ru» проверяет резерв даже при выключенном переключателе. Запросы к Cloud.ru выполняются по условиям и тарифам Cloud.ru.

Ключ Cloud.ru хранится в `data/cloud-backup.json` без шифрования и исключён из Git вместе с папкой `data`. Удаление ключа в настройках отключает резерв. При проверке Cloud.ru список моделей загружается из API, показываются только идентификаторы DeepSeek. Можно также обновить список отдельной кнопкой и сохранить выбранную модель. Если список пуст, проверьте доступ к моделям в Cloud.ru. Смена ключа сбрасывает выбор модели. Чат может использовать резервную модель, когда основной сервис отклонил ключи или сообщил о лимите (401, 402, 429). При сетевом сбое, ошибках сервера или обрыве ответа автоматическая повторная генерация не запускается: запрос мог уже быть обработан и оплачен. Успешный ответ `/models` не гарантирует доступ к конкретной модели.

## Чат и внешний вид

Для чата нужна запущенная и настроенная PostgreSQL: без неё история не сохраняется и отправка сообщений недоступна. В настройках укажите адрес и ключ AI STAR, загрузите список моделей и сохраните выбор. Для резерва включите Cloud.ru, введите его ключ и отдельно выберите DeepSeek. При резервном ответе отображается поставщик и модель; тарификация Cloud.ru может отличаться.

Ответ поступает постепенно. Сообщение пользователя и место для ответа записываются в одной транзакции до запроса; полученный текст сохраняется примерно раз в секунду и при завершении. При сбое может быть потеряна часть, полученная после последней записи. Незавершённые ответы при следующем запуске отмечаются прерванными. Для повторной отправки с тем же идентификатором запрос не запускается второй раз. В следующий запрос включается до 20 последних сообщений. Тема и размер текста настраиваются в верхней панели чата и сохраняются в браузере.

Переписка загружается страницами по 50 сообщений: более ранние подгружаются при прокрутке вверх. Для записи используются до четырёх соединений PostgreSQL; старые сообщения сохраняются. При обновлении базы автоматически применяется миграция, для которой необходимы права на изменение таблиц и создание индексов. Перед обновлением рекомендуется иметь резервную копию базы.

## Граф связей

В левом меню откройте «Граф связей». Страница показывает записи из таблицы `memories` и отношения из `knowledge_links` в PostgreSQL. Нажатие на точку показывает сохранённое содержание и источник, если он указан. Направление стрелки идёт от исходного факта к связанному; название связи доступно при наведении на линию. Масштаб меняется колесом мыши, фон можно перемещать.

Для производительности за раз отображается не более 120 последних записей и 350 связей между ними; если отображена только часть, об этом сообщается. Если память пуста, граф будет пустым. Фоновая очередь обрабатывает новые сообщения с явными фактами и создаёт простые связи по общей теме. Это ограниченная обработка, а не полноценное понимание произвольного текста.

## Память, источники и поиск

После сохранения нового сообщения очередь в фоне проверяет явные формулировки: «Запомни: ...», «Меня зовут ...», «Я предпочитаю ...» и «Мой проект называется ...». Обычно обработка происходит в течение 15–30 секунд при работающем приложении. Старые сообщения автоматически не перерабатываются. Очевидные ключи и пароли отфильтровываются, но это не гарантирует обнаружение всех секретов. Общие темы создают предположительные связи, а не доказанные отношения.

Одинаковые нормализованные факты объединяются, источники каждого сообщения сохраняются. Противоречия автоматически отслеживаются только для имени и часового пояса в поддерживаемых формулировках. Версии с конфликтом не передаются модели до ручной проверки. В графе можно открыть исходное сообщение, подтвердить или отклонить факт; подтверждение одной версии помечает другие версии того же однозначного поля как заменённые, не удаляя их. Без настоящего источника достоверность не устанавливается.

Без pgvector работает локальный поиск по общим словам. Для смыслового поиска установите расширение pgvector в PostgreSQL, включите его в базе командой `CREATE EXTENSION IF NOT EXISTS vector`, затем перезапустите Hanayorina. Укажите в локальном `.env` переменную `MEMORY_EMBEDDING_MODEL` с точным ID поддерживаемой модели эмбеддингов основного OpenAI-совместимого API. Не используйте обычную чат-модель вместо модели эмбеддингов. Если расширения или модели нет, чат продолжает работать с поиском по словам.

При включённой модели эмбеддингов тексты фактов и запросов отправляются основному настроенному провайдеру. Возможна оплата: фоновая индексация ограничена одним запросом не чаще чем раз в пять минут; при ошибке индексация приостанавливается до перезапуска. Поиск в активном чате может потребовать отдельный запрос эмбеддинга. Тексты могут передаваться в модель вместе с историей; поиск по смыслу и точность извлечения необходимо проверить на конкретном провайдере. Резервный Cloud.ru для эмбеддингов не используется.
